# إعادة الهيكلة

## الاستخدام
```
أعد هيكلة [الملف/الدالة] باستخدام [النمط]

الهدف:
- [تحسين 1]
- [تحسين 2]

الحفاظ على:
- نفس الـ API/الواجهة
- التوافق مع الكود الحالي
- الاختبارات الموجودة

النتيجة:
- الكود الجديد
- ملخص التغييرات
- أي تحذيرات
```

## خطوات Refactoring

1. **فهم الكود الحالي**
   - ما الذي يفعله؟
   - كيف يُستخدم؟
   - ما зависиياته؟

2. **التخطيط**
   - ما النمط/الهيكل الجديد؟
   - كيف سأحافظ على التوافق؟

3. **التنفيذ**
   - تغييرات صغيرة متتالية
   - اختبار بعد كل تغيير

4. **المراجعة**
   - هل تعمل جميع الاختبارات؟
   - هل الأداء أفضل؟
   - هل الكود أوضح؟

## أنماط Refactoring الشائعة

| من | إلى |
|----|-----|
| دالة طويلة | عدة دوال صغيرة |
| God Object | Single Responsibility |
| كود مكرر | DRY (Don't Repeat Yourself) |
| Hard-coded values | Constants/Config |
| تبعيات ملتصقة | Dependency Injection |
